# Telemetry file format

Format identifier: `vehicle-telemetry-csv`, version 1.

The simulator writes one CSV file per recording. The format is meant to be
read by spreadsheets, plotting scripts and other tools without a custom
parser.

## Layout

A file is UTF-8 text with `\n` line endings, in this order:

```text
# format = vehicle-telemetry-csv
# format_version = 1
# generator = <product name and version>
# <key> = <value>                           metadata, any number of lines
# channel <name> [<unit>] <description>     one line per column, in column order
<name>,<name>,...                           header row
<value>,<value>,...                         one row per sample
```

- Lines starting with `#` are comments. Most CSV readers can be told to skip
  them (`comment='#'` in pandas, for example).
- Values are decimal numbers with `.` as the decimal separator and at most
  six decimal places. There is no thousands separator and no quoting.
- An empty field means the value was not finite at that sample.
- Rows are evenly spaced in simulated time. The spacing is
  `1 / sample_rate_hz` from the metadata.

## Metadata keys

| Key | Meaning |
| --- | --- |
| `format`, `format_version` | Identify this layout. Readers should check both. |
| `generator` | Product name and version that wrote the file. |
| `car`, `car_name` | Car identifier (data file stem) and display name. |
| `track` | Track identifier. |
| `tick_rate_hz` | Physics rate of the session. |
| `sample_rate_hz` | Rows per second of simulated time. |
| `content_hash` | Hash of the data files the session loaded. |
| `surfaces` | Surface index to name, as `index:name` pairs. Decodes the `*_surface` columns. |
| `note` | Reminder that parameters are placeholders unless marked measured. |

Readers must ignore metadata keys they do not know.

## Conventions

- SI units throughout. Angles are radians.
- Axes follow ISO 8855: x forward, y left, z up. Lateral quantities are
  positive to the left; yaw is positive counter-clockwise seen from above.
- Slip ratio is positive under drive and negative under braking. A positive
  slip angle produces a positive (leftward) lateral force.
- Wheel prefixes: `fl` front left, `fr` front right, `rl` rear left, `rr`
  rear right.
- Steering torque and every force-feedback channel are positive when the
  torque pushes the steering wheel to the left.

## Force-feedback channels

The pipeline stages are logged separately so clipping and latency can be
measured offline:

- `ffb_raw_nm` is the pre-filter signal: the physical steering torque.
- `ffb_filtered_nm` is the same signal after gain, low-pass and slew limit.
  Cross-correlating it with `ffb_raw_nm` gives the latency the filters add.
- `ffb_requested` is the total demand as a fraction of the device's peak
  torque. Samples where its magnitude exceeds the preset's soft-clip knee are
  being compressed.
- `ffb_output` is the post-filter signal sent to the device, and
  `ffb_clipped` is how much the soft clip removed.

When a recording is made without a steering device (for example by the
headless binary), `ffb_effects_nm` and `ffb_wheel_velocity_rad_s` are zero
because there is no physical wheel to measure.
